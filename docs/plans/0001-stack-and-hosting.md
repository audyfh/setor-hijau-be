# ADR 0001: Stack and hosting

Status: Accepted (project owner), 2026-11-01

## Context
Backend-first build of a multi-tenant SaaS for a course final project and portfolio. The owner uses Docker and has Google Cloud credit. A fallback is wanted in case the Google Cloud credit cannot be used.

## Decision
- Language/framework: Go with Gin for HTTP.
- Database access: PostgreSQL 16 via pgx v5, queries generated by sqlc, migrations by golang-migrate (plain SQL).
- Architecture: modular monolith, one deployable, one database.
- Local development: Docker Compose (api + postgres).
- Primary hosting: Google Cloud Run (API container) + Cloud SQL for PostgreSQL. Secrets in Secret Manager, injected as environment variables. Migrations run as a separate job/step.
- Fallback: Supabase used as a Postgres-only database. The switch is a change of `DATABASE_URL`. Supabase Auth, Storage, and client libraries are not used; authentication stays application-owned.

## Alternatives considered
- Chi or net/http instead of Gin: lighter, but Gin was the owner's choice.
- GORM instead of sqlc: faster for plain CRUD, but harder to guarantee tenant filtering and ledger query behavior. sqlc keeps SQL explicit and typed.
- Compute Engine + Docker Compose: simplest and cheap, but self-managed server. Cloud Run is managed and scales to zero.
- GKE: unnecessary for this scale.
- Supabase Auth/Storage: more coupling to the vendor and conflicts with app-owned auth and the portability goal.

## Consequences
- Portability rules: standard PostgreSQL features only, plain SQL migrations, no cloud SDKs outside `internal/platform`.
- Behind Supabase's transaction pooler, pgx must not rely on cached prepared statements (use simple protocol or an appropriate describe-cache mode), and `SET LOCAL` per transaction is used for tenant context if row-level security is adopted.
- If Google Cloud becomes unusable, the API container also needs another container host. That choice is a new ADR at that time.
- Verified end-to-end in milestone M7: same image, only `DATABASE_URL` differs.
